# Security Policy

## Reporting a vulnerability

**Do not open a public issue.** Report privately through
[GitHub Security Advisories](https://github.com/iconmind/iconmind/security/advisories/new)
or by email to **security@iconmind.dev**.

You can expect a first response within 24 hours and an assessment within 7 days.

## Scope

IconMind ships SVG files and thin wrappers around them. There is no server, no
database, and no account system, so the realistic attack surface is narrow. Things we
consider in scope:

* **Malicious content in an SVG** — scripts, external references, embedded data.
  The validator rejects `<script>`, `<style>`, `<image>`, `<use>`, event handlers,
  and external URIs, and CI runs it on every pull request. A bypass is a
  vulnerability, and we would very much like to hear about it.
* **Supply chain** — a compromised dependency, or a published package whose contents
  do not match this repository. All packages publish with
  [npm provenance](https://docs.npmjs.com/generating-provenance-statements), so you
  can verify any release against the workflow run that produced it.
* **Build and release pipeline** — anything that could inject content into a
  published package.

Out of scope: vulnerabilities in applications that merely *use* IconMind, and reports
generated by automated scanners without a demonstrated impact.

## Supported versions

The latest minor release of each major version receives security fixes.
