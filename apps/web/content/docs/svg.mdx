Every icon page on this site has a copy button for the raw file. If you would rather have
them locally:

```bash
npm i @iconmind/icons
```

## The files

```
icons/<category>/<slug>.svg    the source, one file per icon
dist/metadata.json             names, tags, categories, relationships
dist/sprite.svg                every icon as a <symbol>
```

## Sprite

```html
<svg width="24" height="24"><use href="/sprite.svg#im-agent" /></svg>
```

Symbol ids are the slug prefixed with `im-`.

## Inline

```html
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24"
     fill="none" stroke="currentColor" stroke-width="2"
     stroke-linecap="round" stroke-linejoin="round">
  <!-- paste the paths -->
</svg>
```

Icons inherit `currentColor`, so colour comes from CSS. Nothing in the set relies on
colour to carry meaning — every icon has to read in monochrome.

## Metadata

The full database — descriptions, tags, keywords, lookups — lives on its own subpath, so
importing it is a decision rather than an accident. It is ~180 KB gzipped: right for a
build script, a docs site or a search index, wrong for a client bundle.

```js
import { getIcon, iconsIn, categories } from "@iconmind/icons/metadata";

getIcon("agent");        // one icon, aliases resolved
iconsIn("mcp");          // every icon in a category
categories;              // categories with counts
```

The bare entry point costs a few hundred bytes and tells you only what is here:

```js
import { version, counts } from "@iconmind/icons";
```

## Download the whole set

Two archives, rebuilt with every release:

- [iconmind-svg.zip](/download/iconmind-svg.zip) — every icon, all six cells (`outline` and `duotone` × `thin`, `regular`, `bold`), one folder per icon.
- [iconmind-png.zip](/download/iconmind-png.zip) — one 512 px transparent PNG per icon, outline regular in black.

Both carry the MIT licence file. For a single icon in another size, colour or format — PNG at 16 to 512 px, WebP, a favicon `.ico`, JPEG — use the **Download** menu on the icon's own page: it renders from the exact variant and weight you have on screen.

## From a CDN, no install

The npm package is mirrored by jsDelivr, so the sprite and any single cell are one URL away:

```html
<svg width="24" height="24">
  <use href="https://cdn.jsdelivr.net/npm/@iconmind/icons/dist/sprite.svg#im-agent" />
</svg>
<img src="https://cdn.jsdelivr.net/npm/@iconmind/icons/icons/agents/agent/duotone-bold.svg" width="24" height="24" alt="Agent">
```

Pin a version (`@iconmind/icons@0.5.0`) in anything that ships; the unpinned URL follows the latest release.

## Iconify

The set is published as an Iconify collection too — `@iconmind/icons/iconify.json`, prefix `iconmind`, with a `-duotone` twin for every icon and every alias the set knows — so it works wherever Iconify does: the Figma plugin, VS Code, `unplugin-icons`, the Tailwind, Nuxt and Astro icon modules, and [icones.js.org](https://icones.js.org).

```html
<span class="iconify" data-icon="iconmind:agent"></span>
<span class="iconify" data-icon="iconmind:vector-database-duotone"></span>
```
